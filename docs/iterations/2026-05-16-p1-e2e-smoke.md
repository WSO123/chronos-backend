### 背景

P1 的 Capture、Inbox、Today、Task Detail、Focus、Daily Report 和 Me 已经具备基础 API 能力。接下来需要一套轻量但完整的本地验证方式，避免后续开发只看单点测试，忽略主路径是否仍然顺畅。

### 目标

- 提供本地 demo seed，便于前端联调和手动体验。
- 提供 P1 smoke 脚本，跑通核心执行闭环。
- 在 README 中沉淀启动、seed、smoke 和测试命令。
- 不引入真实 LLM、异步 worker 或复杂测试编排。

### 非目标

- 不做生产级 fixture 系统。
- 不重置或清空开发数据库。
- 不覆盖前端验收标准。
- 不替代服务层 / API 层单元测试。

## 4. 需求范围

### 功能清单

| 功能 | 描述 | 优先级 | 备注 |
| --- | --- | --- | --- |
| Demo Seed | 创建 demo 用户、目标、任务、待处理输入、今日计划和日报 | Must | 不重置数据库 |
| P1 Smoke | 通过 API 跑通 Capture -> Inbox -> Today -> Task Detail -> Focus -> Report -> Me | Must | 使用本地 DB |
| README 更新 | 补充 P1 验收命令和项目结构 | Must | 指导后续迭代 |

### 用户故事

```text
作为 Chronos 开发者，
我希望每次迭代后能快速跑通 P1 主链路，
以便确认复杂能力没有破坏用户最核心的执行闭环。
```

### 主要流程

```text
uv run python scripts/dev_seed_demo.py
-> 输出 demo X-User-Id
-> 前端 / API 文档可直接使用 demo 数据

uv run python scripts/smoke_p1_execution_loop.py
-> Capture
-> Inbox confirm
-> Task Breakdown / AIJob
-> Today
-> Task Detail
-> Focus complete
-> Daily Report
-> Me Overview
```

无新增事件。Smoke 覆盖已有事件：

## 9. Review 记录

- Smoke 脚本默认创建独立用户，避免旧 active focus session 或已完成任务污染验证。
- Demo seed 默认复用 `demo@chronos.local`，方便前端稳定拿到同一个联调用户。
- 本轮不引入 DB reset，避免误伤本地开发数据。
